# 语雀文档迁移参考

## 输入方式

### 内置浏览器（默认）

用户提供语雀网页链接时，默认在 Codex 内置浏览器（`iab`）打开，复用其中的登录会话；尚未登录时让用户在内置标签页完成。只有用户明确指定其他浏览器时才使用外部浏览器。从请求中明确以下信息，仅对缺失或含糊的信息提问：

1. 语雀文档链接、选中的文档或知识库页面；
2. 迁移范围是一篇文档，还是知识库或目录下的全部文档；
3. Obsidian 笔记库路径，以及目标目录或具体笔记文件名；
4. 存在同名笔记时是否允许覆盖。

查看内置浏览器标签页并复用已有会话，只导出或下载指定范围。遇到登录限制、导出限制、客户端渲染或仅能通过页面访问的附件时，按浏览器流程判断是否能完整获取正文；无法获取时报告限制并请求本地导出，不提取凭据或绕过访问控制。不得将 Cookie、令牌或私有浏览器存储写入笔记库或报告。

下载后，按下列本地输入方式处理文件或目录。浏览器保存的 HTML 页面可能需要先清理无关内容；保留正文和链接，并记录其引用的远程资源。

- **Markdown 文件或目录**：处理 `.md` 和 `.markdown` 文件，重写链接和附件引用后写入笔记。
- **HTML 文件或目录**：通过保守的标准库 HTML 解析器转换 `.html` 和 `.htm` 文件，处理标题、段落、列表、链接、图片、代码、引用和简单表格，并复核转换结果。
- **ZIP 压缩包**：解压到临时目录后，按导出目录处理；不将压缩包本身复制到笔记库。
- **Lakebook 知识库导出**：先使用下文暂存流程，生成 Markdown 后再交给迁移转换器；不要将 .lakebook 当成 ZIP 或直接传给主转换器。

在 `--root-folder` 指定的目标目录下保留源目录层级。语雀导出中常见的 `_sidebar.md` 按普通笔记处理，避免丢失导航信息。

### Lakebook 暂存与验收

实测 .lakebook 是 tar 容器，内部包含一个 `$meta.json` 和按文档 slug 命名的 JSON 文件。元数据中的 `meta` 是 JSON 字符串；其中的 `book.path` 提供知识库来源 URL，`docs` 提供文档清单。文档 JSON 中的 `doc.body` 是 HTML，`body_asl` 是编辑器内部格式，不能直接当成 Markdown。

运行 `python3 scripts/lakebook_to_markdown.py BOOK.lakebook EMPTY_STAGING_DIR`。脚本只读取需要的归档成员，不整包解压；拒绝不安全 slug、元数据不匹配、非空暂存目录、未知正文格式，以及有编辑器内容却没有 HTML 正文的情况。同名标题使用 -2 等后缀。重复 `--slug SLUG` 可筛选文档；只有来源 URL 经界面核实时才以 `--base-url BOOK_URL` 补充或修正。

先检查脚本输出的逐篇来源、目标、状态、正文长度和 `content_source`。默认使用导出的 `body`，为空时回退到 `body_draft`；如 `draft_differs` 为 true，应说明有不同草稿，用户需要草稿版本时先澄清。真正空白的文档只生成来源属性区，并在迁移汇总中说明。暂存器生成的属性区会由主转换器原样保留。

暂存器当前只支持已验证的 lake/HTML 正文。知识库目录层级不会自动重建，文档平铺在指定目录；用户要求保留目录树时，先核实元数据并建立显式映射，不声称已保留未验证的层级。遇到非 JSON 归档文件时停止并提示单独检查附件，不能静默丢弃它们。HTML 中远程图片保留 URL，由主转换器报告；不会自动形成离线附件。转换器无法保证复杂公式、嵌入卡片或视觉样式完全还原，须与源页面核对。

预演及写入示例：

```bash
python3 scripts/yuque_to_obsidian.py EMPTY_STAGING_DIR VAULT --root-folder BOOK_NAME --dry-run
python3 scripts/yuque_to_obsidian.py EMPTY_STAGING_DIR VAULT --root-folder BOOK_NAME --apply --report REPORT.json
```

报告与暂存材料保存在工作目录；不要把凭据、导出容器或中间 JSON 写进笔记库。写入后逐篇比对 Markdown 和迁入文件，并检查报告中的跳过、冲突及链接/附件问题。

## 目标映射

用户指定目录时，在该目录下保留相对源路径和文件名。用户指定具体文件名时，仅迁移一篇源文档，使用指定的文件名；不得擅自重命名一批文档。写入前展示源文档到目标文件的映射。除非用户明确选择另一个笔记库，否则目标不能位于所选 Obsidian 笔记库之外。

## 输出行为

每篇源文档生成一个 `.md` 文件。规范化相对路径，防止路径越界。两个源文件映射到同一路径时，后者添加 `-2`、`-3` 等后缀。已有目标文件会记录为冲突并跳过，除非使用已获授权的 `--overwrite`。

没有属性区的笔记会添加简短 YAML 属性区，包括 `title`、`migrated_from` 以及提供了来源链接时的 `source_url`。已有属性区保持不变。`--no-frontmatter` 禁用新增属性区，但不删除已有属性区。

本地图片及其他链接文件复制到 `--attachments-dir` 指定的目录（默认为 `attachments`），引用改为相对笔记的路径。远程 `http(s)` 和 `data:` 资源引用保持不变；远程图片会列入报告。

默认只生成只读计划，使用 `--apply` 才执行写入。预演会打印文档映射和问题列表。写入时，报告默认为笔记库根目录下的 `.yuque-migration-report.json`，可通过 `--report` 指定其他路径；需要保留历史报告时，为每次迁移在工作目录设置独立报告路径。报告记录计划、写入和跳过的文档、复制的附件、冲突、缺失的本地附件、远程资源、未解析的文档链接，以及 HTML 或引用式链接警告。脚本不会删除文件。

附件文件名包含内容哈希，重复迁移时复用内容相同的附件。只规划和复制本次实际写入笔记的附件。链接采用 URL 编码的相对路径，兼容 Obsidian Markdown。行内代码和围栏代码块不重写。引用式链接和已有 Obsidian 双链保持不变，并提示人工复核。指向迁移范围外文档的语雀网页链接仍为外部链接；脚本无法自动推断网页 URL 与导出文件的对应关系。

单篇源文件的本地附件默认必须位于其父目录内。附件位于同级文件夹时，通过 `--asset-root` 指定经确认的导出根目录。遇到无效 UTF-8 编码会报错，不静默替换字符。HTML 转换是降级方案，不保证与原页面视觉完全一致；优先使用语雀原生 Markdown 导出。

## 授权与验收

以预演结果作为写入前的检查点。用户要求将指定文档迁移到指定目标，已授权在那里新建文件，但仍须满足文件系统权限；覆盖已有文件或目标不明确时另行确认。迁移后检查报告并在 Obsidian 中打开代表性笔记，跟进未解析链接和远程资源。仍存在远程附件时，不得宣称已完成全离线迁移。
